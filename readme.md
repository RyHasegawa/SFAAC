# SFAAC

SFAAC is constructed for analyzing biases in language models induced by sub-formula level structures in the paper "Neuro-Symbolic Reasoning with External Inference Tools Mitigates Bias from Sub-Formula Level Logical Structure", accepted for EMNLP 2026 main.

SFAAC is a dataset created by adding sub-formula level annotations to the test set of AAC (Bets et al., 2021) ([paper](https://aclanthology.org/2021.iwcs-1.7/)) ([github](https://github.com/debatelab/aacorpus)). 

## Details of sub-formula annotation

![Overview](images/overview_annotation.png)

AAC is a synthetic corpus with templates, and formulas with the same complexity level are classified into the same group. The label is true/false(not true), and each false formula is generated from a true formula by flipping the negation of the final atom. Therefore, the difficulty of the formulas in the same group is largely determined by the sub-formula factors around the final atom, such as the **negation of the final atom**, and **the number of atoms in the conclusion's consequent**. We newly annotate these sub-formula factors for formulas in AAC.

## Format

Each file is JSON Lines, with one Evaluation Pair per line. Newly added keys in SFAAC are following:

- `num_atoms_CC`: the number of atoms in the conclusion's consequent of the text., one of `0`, `1`, or `2`. Main annotation.
- `final_atom_neg`: the negation of the final atom, either `positive` or `negative`. Main annotation.
- `evaluation_text`: Input text for evaluation.
- `gold_label`: gold label of `evaluation_text`, either `true` or `false`.
- `Qwen3`: whether the item is used or not with Qwen3 in our paper.

Other keys are originally generated by AAC.

## Evaluation environment

Set `OPENAI_API_KEY` for GPT models or `GEMINI_API_KEY` for Gemini models. The environment used for this project was tested with Python 3.13, PyTorch 2.8.0, CUDA 12.8, and bitsandbytes 0.48.2.

### Prover9 and Mace4

Prover9 and Mace4 are external commands from the LADR tool suite, not Python packages. Install both programs on the local system and ensure that the `prover9` and `mace4` executables are available on `PATH`.

Z3 does not require a separate system installation because its Python package is included in `requirements.txt`.

## Running evaluations

Run all commands from the repository root. Select one of `aac_naive`, `aac_CoT`, `aac_CoT_Logic`, `aac_z3`, or `aac_prover9` as the prompt style.

For GPT or Gemini Batch API execution, submit a batch and then collect it after completion:

```bash
venv/bin/python evaluation/batch_1_submit.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
venv/bin/python evaluation/batch_2_collect_results.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
venv/bin/python evaluation/3_evaluate_answers.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
```

For a local model (Qwen/Qwen3-30B-A3B-Thinking-2507), generate, extract, and evaluate answers in order:

```bash
venv/bin/python evaluation/local_1_generate_answer.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
venv/bin/python evaluation/local_2_extract_answer.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
venv/bin/python evaluation/3_evaluate_answers.py --data_dir data/sfaac-1420.jsonl --prompt_style aac_naive --model_name MODEL_NAME
```

Add `--qwen3-only` to use the 284 records marked for Qwen3. Intermediate files and results are written under `batch_input/`, `cache/`, `output_json/`, and `output_csv/`.
